# Use Cases（Step 1）

このファイルは Step 1 の作業シートです。前半が説明、後半が自分で埋める欄です。

## Step 1 でやること

Initial Development Slice の範囲で、**生産管理担当者がシステムを使って行う操作を 3〜5 個に絞り、それぞれ「誰が・何をきっかけに・何を入力し・何を判断し・何が結果として残るか」を言葉にする。**

> Slice: 既に工程が定義されている製造オーダーについて、各工程を設備と日付に割り当て、工程順序と設備能力を満たす生産スケジュールを作成・変更する。

この Step では、まだ Entity / Aggregate / テーブルを考えない。業務の言葉だけで書く。

## Epic / User Story / Use Case の違い

| 粒度       | 何を表すか                                         | 例（この Slice とは別の題材: 図書館）        | このプロジェクトでの置き場所 |
| ---------- | -------------------------------------------------- | -------------------------------------------- | ---------------------------- |
| Epic       | 大きな目的のまとまり                               | 本の貸出を管理する                           | Notion PRD                   |
| User Story | 利用者の要望（〜として、〜したい。なぜなら〜）     | 利用者として、本を借りたい。家で読みたいから | Notion PRD（現在は未記入）   |
| Use Case   | システムに対する 1 回の操作と、その入力・判断・結果 | 本を貸し出す                                 | このファイル                 |

Use Case は、後の Step 2（Domain Rule）の出発点になる。「この操作のときに何が起きたら業務上おかしいか」を Step 2 で考えるので、操作の単位で区切っておく。

## 各 Use Case に書く項目

| 項目       | 意味                                                         |
| ---------- | ------------------------------------------------------------ |
| Actor      | 誰が行うか                                                   |
| きっかけ   | なぜ今この操作をするのか（業務上の出来事）                   |
| Input      | 操作に必要な情報                                             |
| Decision   | 人が判断すること / システムが判定すること                    |
| Constraint | 守られていないと困りそうな条件（候補でよい。詳しくは Step 2）|
| Output     | 操作の結果、何が残る・変わるか                               |

### 記入例（図書館の「本を貸し出す」）

この Slice とは別の題材で、書き方の粒度だけを示す。

- **Actor**: 図書館の窓口担当者
- **きっかけ**: 利用者が本を持って窓口に来た
- **Input**: 利用者、本、貸出日
- **Decision**: 人は「貸すかどうか」を決める。システムは「貸出上限を超えていないか」「その本が貸出中でないか」を判定する
- **Constraint**: 同じ本を 2 人に同時に貸せない / 1 人の貸出冊数に上限がある
- **Output**: 貸出記録が残り、返却期限が決まる。本は貸出中になる

ポイント:

- 名前は「〜する」という動詞で書く
- Decision では、人が決めることとシステムが判定することを分ける
- Constraint は「不便」ではなく「業務として壊れる」ものを意識する（ただし Step 1 では候補を挙げるだけでよい）

## 考えるときの材料

- Notion の Epic「生産スケジュールを作成・調整する」に、対象（工程ごとの予定設定、設備への割り当て、納期からの逆算、急ぎ案件・納期変更に伴う予定変更、後工程への影響確認）と設計上の論点が書かれている
- `README.md` の Primary Persona（香山さん）の Problems に、困りごとの場面が書かれている
- `LEARNING.md` Step 1 に、観点の例がある

自分に問うとよいこと:

- 香山さんは、1 日の中でどんな場面でこのシステムを開くか
- その操作は「保存して何かが変わる」操作か、「見て判断するだけ」の操作か
- 同じ操作に見えても、きっかけが違えば別の Use Case か（例: 新規の割り当てと、設備トラブルによる変更）
- Slice の範囲外に出ていないか（時刻単位の計画、作業者、外注、自動最適化など）
