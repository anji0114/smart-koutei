# Domain Model（Step 3）

Step 2 で決めたルールを、自然に表現できるモデルを考える。

- 入力: [domain-rules.md](./domain-rules.md)（R1〜R5）、[ADR-0003](../adr/0003-rule-strength.md)、[glossary.md](../glossary.md)
- この Step では書かないもの: テーブル・カラム（Step 6）、Aggregate の境界（Step 4）、Repository

## やること

1. **登場する概念を並べる**: 用語集の言葉から始める。足りない概念があれば足す
2. **概念ごとに「何を知っているか」「何を判断・計算するか」を書く**: データの項目一覧ではなく、責務を書く
3. **ルールを誰が守るかを決める**: R1〜R5 を、どの概念が守るか・計算するかに割り当てる
4. **Entity か Value Object かを決め、理由を書く**: 目安は「時間がたっても同じものとして追いかけるか（Entity）」「値が同じなら同じとみなすか（Value Object）」
5. **概念どうしの関係を図にする**: 箱と矢印でよい
