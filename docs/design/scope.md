# Scope（最初の Slice をどこまで絞るか）

最初に作る範囲を、軸ごとに決める検討シート。決まったら「決定」欄を埋め、最後に ADR（Initial scheduling scope）として残す。

## 前提

### 事実

- `README.md` の Initial Development Slice: 「既に工程が定義されている製造オーダーについて、各工程を設備と日付に割り当て、工程順序と設備能力を満たす生産スケジュールを作成・変更する」
- Use Case の担当分け（2026-10-03）: 事務が受注を登録する。課長がスケジュールを作成する
- 開発者の認識（2026-10-03）: スケジュール管理全体は大きすぎて、MVP にならない

### このプロジェクトでの MVP の意味

売れる最小の製品ではなく、**設計の論点を検証できる最小の範囲**（`LEARNING.md`）。そのため、絞るときは次の 3 つが残っているかを確認する。

| 学習の論点                   | 何があれば残るか                                             |
| ---------------------------- | ------------------------------------------------------------ |
| Invariant                    | 破ると業務が壊れるルールが 1 つ以上ある                      |
| Aggregate Boundary           | 複数の製造オーダーが、同じ設備の能力を取り合う               |
| Transaction / Concurrency    | 2 人が同時に同じ設備・同じ日に割り当てると、能力を超えうる   |

**注意: 設備の能力を外すと、Aggregate Boundary と Concurrency の論点がほぼ消える。** 能力は小さくしても残す方がよい。

### 補足

- **2（資源）**: 作業区と設備の違いは README の Current Unknowns にある。両方を入れると、その違いを先に決める必要がある。最初はどちらか 1 つにして、違いは次の Slice で扱う方が進みやすい
- **3（時間）**: 複数日にまたがると「1 日目に 5 時間、2 日目に 3 時間」のような配分ルールが必要になる。最初は 1 日に収まる前提にすると、能力チェックが単純になる
- **6（納期）**: 業務上は重要。ただし最初は工程順序と能力だけで、学習の論点はすべて残る
- **8（前提データ）**: 製品・工程・設備の登録は事前条件として、画面を作らず初期データで入れる。Data Model から始めることを避けられる

## 後回しにしたもの（必ず対応する）

今回の Slice では扱わないが、後で必ず対応すると決めたもの。今のモデルを先回りして抽象化はせず、対応するときに「どこが変わるか」を確かめる（`LEARNING.md` Step 8 の要求変更として扱う）。

| 内容 | 決めた日 | 備考 |
| --- | --- | --- |
| 並列: 依存先が一部完成した時点で次の工程を始める（例: 1000 個中 100 個できたら組み付け） | 2026-10-03 | 開発者が「絶対する」と明言 |
| 依存する工程を依存先と同じ日に始めてよいかの判定アルゴリズム | 2026-10-03 | 本来の仕様は「同じ日 OK」。判定方法は未定 |
| 開始日に空きがないとき、AI が最適な割当を提案する | 2026-10-03 | 今回は割り当てを拒否する |
| 受注を完了にする（UC-02 の候補）。営業から課長への確認のたびに現場に行く、という困りごとに応える | 2026-10-04 | 開発者は入れたい。まずはスケジュール作成に注力する |
| 割り込み: 急ぎの受注を既存の工程より前に入れる。AI が優先度を見て「ここに入れて、こう変えましょう」と提案する | 2026-10-04 | 今回は新しい工程は設備の順番の最後に入る。「優先度」は新しい概念 |

## 決まった Slice（2026-10-04）

> 課長が、工程と依存関係・加工時間が決まっている受注について、各工程に設備と開始日を指定してスケジュールを作成する。システムは設備ごとの工程の順番と 1 日の能力時間から、各工程が使う日と時間を計算する。依存関係が崩れた工程は警告で示す。

外れるもの: スケジュールの変更（UC）、作業区、並列（一部完成で次工程を始める）、受注をまたぐ依存、納期チェック、後工程の自動追従、登録画面、権限、正規以外の案
