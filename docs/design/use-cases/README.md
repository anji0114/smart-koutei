# Use Cases

生産管理担当者がシステムに対して行う操作を、1 ファイル 1 Use Case で書く。このファイルは一覧・書き方・候補の洗い出しをまとめる。

## 一覧

| ID  | 名前 | 種類 | Slice | 状態 |
| --- | ---- | ---- | ----- | ---- |
|     |      |      |       |      |

- 種類: **変更**（保存すると何かが変わる）/ **参照**（見て判断するだけ）
- Slice: どの Slice で追加したか（いまは `Initial`）
- 状態: **下書き** / **レビュー済み**

## Use Case とは

Epic・User Story との違い:

| 粒度       | 何を表すか                                           | 例（別の題材: 図書館）                       | 置き場所          |
| ---------- | ---------------------------------------------------- | -------------------------------------------- | ----------------- |
| Epic       | 大きな目的のまとまり                                 | 本の貸出を管理する                           | Notion PRD        |
| User Story | 利用者の要望（〜として、〜したい。なぜなら〜）       | 利用者として、本を借りたい。家で読みたいから | Notion PRD        |
| Use Case   | システムに対する 1 回の操作と、その入力・判断・結果 | 本を貸し出す                                 | このフォルダ      |

Use Case は Step 2（Domain Rule）の出発点になる。「この操作のときに何が起きたら業務上おかしいか」を Step 2 で考えるので、操作の単位で区切っておく。

## どこまで書くか

**短くてよい。1 ファイル 1 画面（30〜50 行）に収まる量が目安。**

### 1 つの Use Case の大きさ

担当者が **1 回の作業で達成する 1 つの目的** を 1 Use Case にする。

- 大きすぎる: 「生産スケジュールを管理する」→ 複数の操作を含んでいる（これは Epic）
- 小さすぎる: 「設備を選ぶ」→ それだけでは業務の目的を達成していない（操作の 1 ステップ）
- 判断の目安: 終わったときに担当者が「よし、これは片付いた」と言えるか

### 書くもの

- Actor / きっかけ / Input / Decision / Constraint（候補）/ Output
- 主な流れを 3〜7 行
- 例外・別の流れのうち、**業務ルールに関係するもの**（例: 能力を超えていたとき）
- 迷っていること

### 書かないもの

| 書かないもの                          | 理由                                           | どこで扱うか     |
| ------------------------------------- | ---------------------------------------------- | ---------------- |
| 画面の配置・ボタン操作                | 業務の判断と関係ない                           | Step 7（必要なら）|
| データ項目の一覧                      | Data Model に引きずられる                      | Step 6           |
| ルールの詳細（強制か警告か、境界値） | Step 2 の仕事                                  | `domain-rules.md` |
| Entity / Aggregate などの名前         | 要求より先にパターンを当てはめない             | Step 3〜4        |
| 入力ミス程度の例外（未入力など）      | 業務ルールの発見につながらない                 | 書かない         |

## 進め方

### 1. 候補を洗い出す（30〜60 分）

1. **場面を書き出す**: README のペルソナ（香山さん）の困りごとと、Notion の Epic「生産スケジュールを作成・調整する」の「対象」を材料に、「どんな出来事が起きたときにシステムを開くか」を書く
2. **場面ごとに、画面でする操作を動詞で書く**: 1 つの場面から複数出てよい
3. **変更 / 参照に分ける**: 業務ルールが効くのは主に変更系
4. **Slice に入るか判定する**: 範囲外（時刻単位の計画、作業者、外注、自動最適化など）は下の「Scope 外」へ
5. **似たものをまとめて 3〜5 個に絞る**: 「きっかけ」と「結果」が同じなら 1 つにまとめる

### 2. 選んだものを 1 つずつファイルにする

`_template.md` をコピーして `UC-01-<kebab-case-name>.md` を作り、上の一覧に追加する。

### 3. レビューを受ける

各ファイルの「レビュー記録」に、指摘と対応を残す。
