# UC-01: スケジュールを作成する

- **Slice**: Initial
- **状態**: レビュー済み（2026-10-03）。残りの論点は Step 2 で扱う

## 概要

課長が、受注した製造オーダーの各工程を設備と日に割り当て、スケジュールを作成する。

## Actor / きっかけ

- **Actor**: 課長
- **きっかけ**: 事務が受注を登録し、スケジュールが未作成の受注がある（AI 補足: 元メモ「事務が受注した情報をシステムに入れる」から）

## 事前条件

- 受注（製造オーダー）が登録済みで、工程とその順番が決まっている（AI 補足: README の Slice 定義から）
- 設備が登録済みで、1 日の能力時間が決まっている（例: 8h）
- 各工程の加工時間が決まっている（例: 10h）
- （仮定）時間の単位は日。加工時間が能力時間を超える工程は、複数の日にまたがる
- （仮定）1 工程は 1 設備（機械）で行う
- （仮定）工程の依存は同じ受注の中だけ。受注をまたいで依存しない
- （仮定）依存先の工程が全量終わってから、依存する工程を始める。一部（例: 1000 個中 100 個）できた時点で次の工程を始めることはしない
- （事実）過去に同じ製品を生産していても、今回の工程の順番が過去と同じとは限らない

## Input

（AI 補足。割り当てる単位が決まったら見直す）

- 対象の受注
- 各工程を行う設備と日

## 主な流れ

（AI 補足。割り当てる単位が決まったら見直す）

1. 課長が、スケジュール未作成の受注を選ぶ
2. 課長が、各工程に設備と日を割り当てる
3. システムが、Constraint を満たしているか判定する
4. 課長がスケジュールを確定する

## Decision

- **人が判断すること**: どの工程を、どの設備に、いつ割り当てるか（AI 補足）
- **システムが判定すること**: 下の Constraint を満たしているか

## Constraint（候補）

| #   | 内容                                                                                                                                                                                                                  | 強さ                                                                                                                                                                    | 備考                                                                                                                                                                                                     |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| C1  | 1 つの受注に対して、正規のスケジュールは 1 本だけ。複数あると壊れる                                                                                                                                                   | 禁止                                                                                                                                                                    | 案は複数あってもよい（仮説）                                                                                                                                                                             |
| C2  | 1 つの設備の 1 日に入れる工程の加工時間の合計は、その設備の 1 日の能力時間を超えられない                                                                                                                              | 禁止（常に成り立つ）。2026-10-03 にいったん「後から破れたら警告」としたが、Initial Slice では後から破れる場面がないため禁止に戻した（2026-10-04、`domain-rules.md` Q1） | 日単位。能力時間内なら同じ日に複数の工程が入る。人ではなく設備を基準に考える                                                                                                                             |
| C4  | 加工時間が 1 日の能力時間を超える工程は、複数の日にまたがって割り当てる。課長が開始日を決め、システムが開始日から空いている能力時間を順に埋める。設備ごとに工程の順番を持ち、順番と能力時間から日ごとの時間を計算する | 禁止                                                                                                                                                                    | 下の「例」と「迷っていること」を参照                                                                                                                                                                     |
| C5  | ある工程に依存する工程は、依存先の工程より前に設定できない                                                                                                                                                            | 追加時は禁止。設備の順番のずれで後から破れた場合はアラート（赤表示）で、保存は止めない                                                                                  | 例: 製品 A の組み付け工程は、部品 1・2 の両方の生産が終わってから（合流・分岐あり）。**暫定**: 依存する工程は、依存先が終わった日の翌日から。本来の仕様は「同じ日 OK」（`scope.md`「後回しにしたもの」） |

### 例（2026-10-03 のメモから）

設備の能力時間 8h、工程 1 の加工時間 10h、工程 2 の加工時間 10h の場合:

| 日   | 工程 1 | 工程 2 | 合計 |
| ---- | ------ | ------ | ---- |
| 10/1 | 8h     | -      | 8h   |
| 10/2 | 2h     | 6h     | 8h   |
| 10/3 | -      | 4h     | 4h   |

工程 1 を 10/1 に入れると 10/1・10/2 を使い、工程 2 は 10/2・10/3 になる。

### 取り下げたもの

| #        | 内容                                                                   | 取り下げた理由（2026-10-03）                                                                                      |
| -------- | ---------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| C2（旧） | 1 つの設備に、同じ時間に複数の工程を入れることはできない               | 時間の単位を日にしたため、時間帯の占有ではなく 1 日のキャパで考える形に変更（2026-10-03）                         |
| C3       | 工場のキャパシティ以上にスケジュールを入れようとすると、アラートが出る | 人の稼働と設備の稼働を混ぜて考えていた。人数より設備が多くても同時に動かせるため、設備を基準にする（C2 に一本化） |

## Output

- 受注に対して正規のスケジュールが 1 本でき、各工程に設備と日が決まる（AI 補足）
- スケジュールは全ユーザーが見られる（今回は権限なし）

## 例外・別の流れ

- その設備のその日の能力時間を超える → 割り当てられない（C2）
- 依存先の工程が終わる日以前に設定しようとする → 割り当てられない（C5、暫定で翌日から）
- 割り当ての結果、同じ設備の後ろの工程がずれ、別の工程が C5 を破る → 保存はできる。破れた工程をアラート（赤表示）で示す（C5）

## 迷っていること

- [x] **C2 と C3 の関係** → 設備を基準にし、C3 は取り下げ（2026-10-03）
- [ ] **スケジュールの単位**: 「受注に 1 本」のスケジュール（受注全体のまとまり）と、「設備に入れる工程（スケジュール）」（工程 1 つ分の割当）の 2 つの意味で使われている。言葉を分けるか
- [ ] **受注と製造オーダー**: 同じものか。1 つの受注から複数の製造オーダーができることはあるか
- [ ] **案（仮説）**: 正規以外の案を持つことは、今回の Slice に入れるか
- [x] **時間の単位** → 日単位。設備ごとに 1 日のキャパを持ち、超えるものは入れられない（2026-10-03）
- [x] **1 日の能力時間より長い工程** → 複数の日にまたがる（2026-10-03、C4）
- [x] **C4 の割り振り方** → 課長は開始日だけ決め、システムが開始日から空いている能力時間を順に埋める（2026-10-03）
- [x] **開始日に空きがないとき** → 今回は割り当てを拒否する。将来は AI が最適な割当を提案する（2026-10-03、`scope.md`「後回しにしたもの」）
- [ ] **開始日がすでに埋まっているとき**: 例で工程 2 の開始日を 10/1（空き 0h）にしたら、割り当てられないのか、空いている日まで後ろにずれるのか
- [ ] **同じ日の中の順番**: 例の 10/2 は「工程 1 の残り 2h → 工程 2 の 6h」の順番を持つのか、日ごとの合計時間だけを見るのか（「迷っていること」の中で一番モデルに効く。AI のコメントはレビュー記録を参照）
- [ ] **キャパの単位と値**: 時間（例: 8 時間）でよいか。設備ごと・日ごとに違うか（休日、メンテナンス日など）

- [x] **C5 の依存の範囲** → 受注をまたがない（仮定、2026-10-03）
- [x] **C5 の並列** → なし。依存先が全量終わってから次の工程を始める（2026-10-03）。将来は必ず対応する（`scope.md`「後回しにしたもの」）
- [x] **C5 の合流** → 入れる。1 つの工程が複数の工程に依存してよい（2026-10-03）
- [x] **C5 の分岐** → 入れる。1 つの工程に複数の工程が依存してよい（2026-10-03）
- [ ] **C5 の「前」の判定**: 本来の仕様は「同じ日に始めてよい」（2026-10-03）。ただし、例えば依存先の設備が能力 4h に対して 4h 使い、次の工程の設備が能力 5h に対して 5h 使う日は、同じ日に両方は収まらない。これを判定するアルゴリズムは未定

  - [x] 今回の Slice の暫定 → 「翌日から」（2026-10-03）

- [ ] **C4 の考え方（再検討）**: いったん「A: 日ごとの合計で見る（順番は持たない）」で決めたが、開発者から「同じ日の中の順番は持つ」と訂正（2026-10-03）。例: 能力 8h の日に工程 A（6h）と工程 B（4h）を入れると、どちらかが 2h を翌日に回す。どちらが回すかを持つ
  - [x] → (2) 設備ごとの順番そのものを持ち、順番が変われば日ごとの時間を計算し直す（2026-10-03）。マイナス面（連鎖）も含めて考える
- [ ] **順番の決め方**: 設備の中の順番は、開始日の早い順か、入れた順か、課長が並べるのか
- [ ] **設備の空き日**: 設備が何もしない日（隙間）を許すか。許すなら、工程は「開始日より前には始めない」+「順番で前の工程が終わってから」の遅い方から始まる、のような形になる
- [ ] **連鎖（同じ設備）**: 既存の工程より前に新しい工程を入れると、同じ設備の後ろの工程がすべて後ろにずれる。作成（UC-01）でも起きる
- [x] **連鎖（依存）** → 保存して、C5 が破れた工程をアラート（赤表示）で示す。拒否も自動追従もしない（2026-10-03）。理由: すべてずらすのは負担が大きい。また、破れた箇所を AI が直し方を提案する機能を入れやすい
- [ ] **連鎖（受注をまたぐ）**: 同じ設備には別の受注の工程も並ぶ。ある受注の作成で、別の受注の工程がずれ、その受注のスケジュールが変わる。依存は受注をまたがない（仮定）が、設備の順番は受注をまたぐ

- [ ] **C2 が後から破れる場面**: C4 では設備の順番と能力時間から日ごとの時間を計算するので、順番がずれても工程は後ろに押し出されるだけで、能力時間は超えない。後から超えるのは、次のような場面か
  - 設備の能力時間を後から減らした（例: 8h → 6h、メンテナンス日）
  - 動かせない工程がある（例: 完了した工程。今回の範囲かは未定）
  - 計算し直さずに、日ごとの時間をそのまま残す場合

## レビュー記録

- 2026-10-03（AI）: C4 の例は、次の 2 つのどちらの考え方でも説明できる。どちらを選ぶかで Domain Model と同時更新の扱いが変わる
  - **日別の合計で見る**: 各工程を「日ごとに何時間使うか」に分け、C2 は日ごとの合計で判定する。同じ日の中の順番は持たない。C2 はそのまま使える
  - **設備ごとの順番で見る**: 設備ごとに工程を順番に並べ、1 日の能力時間で区切って開始日・終了日を決める。同じ日の中の順番を持つ。取り下げた C2（旧）の「被らない」に近い

## 元メモ（2026-10-03）

> - 受注情報からスケジュールが作成できること
> - 受注に対してスケジュールは 1 つのみ、複数できた場合壊れる（ただし正規のスケジュールが 1 本あればよく、いくつか案があっても良い（仮説））
> - 一つの機械・設備に対して同じ時間に複数の工程（スケジュール）を入れることはできない（これは時間の単位は後で考える必要がある）
> - 完了したスケジュールはずらすことができない
> - 完了していない工程はスケジュールを調整することができる
> - スケジュールは全ユーザーが見れる（今回は権限なし）
> - 過去に同じ製品を生産していても、過去と同じ工程の順番とは限らない
> - スケジュールのある製品は削除することはできない
> - 受注していない製品も登録することができる（過去のものなど、ただしこれは受注していると言える）
> - 1 工程 1 設備（機械）とする
> - 工場のキャパシティ以上にスケジュールを入れようとするとアラートが出る
